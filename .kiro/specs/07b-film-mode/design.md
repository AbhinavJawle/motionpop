# Spec 07b · Film mode · design

Written in a Claude Code session (2026-11-17). Evidence for every choice below is in `docs/research/film-mode.md`.

## 1. Shape

```
transcript (words + times), format, look
   │  film.direct  (1 call, strong model, thinking HIGH, 2 repairs)
   ▼
Storyboard { thesis, world, carrier, props[≤3], beats[] }      packages/schemas/src/film.ts
   │  timeBeats()  → TimedBeat[] (startMs, endMs, keyMomentMs, tailMs, over, headMs)
   ├──────────────► film.props (1 call)  → { id: svg }
   └─ for every beat, at once (pool of 4):
        film.build  → { title, html, css, script, keyMomentMs }   lint + 1 repair in the router
           │  Critic (sandbox)  → problems
           └─ film.build with `fix`  (up to 2 rounds)  → best version
   ▼
FilmResult { storyboard, props, beats[{ beat, params | null, problems }] }
   │  app: one command replaces the slots; failed beats → quick-mode scene for their words
   ▼
custom slots with params.film → same compiler, preview and render
```

`makeFilm` (`packages/ai/src/film/make-film.ts`) is pure orchestration: the router, the lint, the kit reference and the critic are passed in. The app passes Firebase AI Logic and a sandboxed frame; the lab passes Vertex and a headless browser.

## 2. Why builders work in parallel
A builder never sees another builder's code. Continuity comes from three shared things instead:
- **The storyboard.** World, recurring element, and one seam per cut that both sides read (a ledger of seams, written before any code).
- **The kit.** `tl.enter(kind)` and `tl.exit(kind)` are the two halves of each seam with fixed distances, times and eases, so two beats written apart meet with the same direction and speed. The map is a pure function of its view, so two beats that set the same view draw the same pixels (a `match` seam needs nothing else).
- **Shared drawings.** Drawn once, reused by id.

Parallel building makes a 40 s film take about as long as its slowest beat plus the storyboard (measured: 3 min 43 s with repairs on the strong model, most of it two repair rounds) instead of the sum of all beats, and lets one beat be rebuilt later without its neighbours.

## 3. Schemas (`packages/schemas/src/film.ts`)
`StoryboardSchema`, `StoryBeatSchema`, `StorySeamSchema`, `StoryPropSchema`; `timeBeats(board, words, durationMs)`; `storyboardIssues(board, words, durationMs)`; `spokenNumbers`, `unspokenNumbers`. Seam kind → tail and stacking is a table in code (`SEAM_TAIL_MS`, `SEAM_OVER`), never the model's choice.

`customParams` (spec 15) gains optional `film { tailMs, over, headMs }`, `props`, `cues`. Old custom graphics parse unchanged.

`EditorProject` gains optional `film { storyboard, props, madeAt, model }` (task 9).

## 4. Runtime and compiler
- `CompileSlot.tailMs` and `.over`: the clip's `data-duration` is the slot plus its tail; clips get a `z-index` so the outgoing beat is in front (`out`) or behind (`in`). Captions and the lens sit above. Slot times in the project never overlap.
- `CompileInput.film`: no drifting backdrop; grain is laid over the graphics too (60 % strength), so cards and maps share the paper's texture.
- Engine: a film beat (`custom` with `params.film`) gets no whole-frame seam and no runtime push-in, and is seeked through its tail. The lens draws no paper sweep at a film cut.
- `custom` words carry their text, so scripts time things by word.

## 5. The kit (`packages/motion/src/film/`)
`timeline.ts` (tweens declared once, every property computed from the list on each seek; `from/to/fromTo/set/draw/wipe/count/words/fn/each`; `at` = start, `on` = land on a spoken word), `kit.ts` (`mp`: frame and voice, `sheet`, `paper`, `mark`, `line`, `icon`, `dots`, `map`, `prop`, `fit`, `sfx`, colours, seams), `map.ts` (Natural Earth flat map as SVG, log-zoom camera, halftone held at screen size, routes, pins, labels, scatter), `icons.generated.ts` (144 Lucide icons, ISC, generated by `scripts/build-icons.ts`), `doc.ts` (the reference the model reads, and the example beat), `critic.ts`.

The kit is a superset of spec 15's helpers, so the old prompt and old graphics keep working. Reuse: `engine/materials.ts` (paper, torn edges, tape), `engine/decor.ts` (highlighter, marker circle, underline), `scenes/map-zoom/geo.ts` and `places.ts`, `core/*`.

Lint changes (spec 15 `lintCustom`): `return tl;` is accepted (the build still refuses anything without a `seek`); `parent`, `top`, `self`, `frames`, `opener`, `location` are only rejected as bare identifiers, not as option keys or properties (the shadowed globals make them `undefined` anyway). `lintProp` checks one shared drawing.

## 6. The Critic (`film/critic.ts`, `window.__motionpop.inspect`)
Measures the DOM at chosen times (purity, a 24-sample motion pass, the opening, the settled frame after the key moment, the end of the tail). Reports `{ rule, level: 'fix' | 'note', atMs, hint }`; `criticText` turns the blocking ones into the repair message. It runs inside the composition, so the same code serves the preview frame, the render preflight and the lab.

In the app (task 8) the critic runs in a hidden sandboxed iframe (`sandbox="allow-scripts"`, opaque origin) holding a one-slot composition; the report comes back by `postMessage`. Generated code never runs in the app's origin.

## 7. Cost
`film` is a unit action: 5 credits per started 30 s (`costOf('film', units)`), in the one price list. The three model tasks carry no price of their own. Measured model cost for the 37.5 s Suez film on the strong model: about $0.29 (19 calls). At 10 credits for that film the margin holds at any credit price above 3 cents.

## 8. Not in this spec
- A picture check by a vision model on stills (the measured critic misses "the map is hidden behind a blue box"); a cheap multimodal pass per beat is the next step.
- Generated images inside film beats (spec 07 R4 assets through `mp.image`).
- The Claude provider for builders (spec 15 R4).
- Sequential building with the previous beat's code in context (kept as a lab comparison only).

## 9. Testing
- Property tests: `timeBeats` tiles any valid storyboard (no gap, no overlap, integer ms, tails inside the next beat); `storyboardIssues` is empty exactly for boards that tile; timeline `seek(t)` is pure (random order equals sequential) for random tween lists; the map camera is pure; `unspokenNumbers` never flags a spoken figure.
- Unit: seam halves (exit ends where enter starts, same sign), lint table additions, `lintProp`, critic rules on fixture beats (happy-dom for logic, the lab for layout), `makeFilm` with a fake router (repair loop, failed beat, cancelled, props failure).
- `kitExample()` passes the lint, `customParams`, and `assertSeekPure` in every format.
- Lab: `pnpm --filter @motionpop/motion film:lab` runs the Suez voiceover end to end against real models (paid, cents; never in CI).

## 10. Correctness properties
- P1. Film beats never overlap in project time; only clips overlap, by at most the tail.
- P2. The same project JSON gives the same frame at any `t` in preview and render (kit and critic use no clock or randomness).
- P3. No figure reaches the screen that the narration doesn't say (storyboard check + critic), except counting numbers 0 to 10.
- P4. A film always covers the whole voiceover: every span is a built beat or a quick-mode scene.
- P5. Credits: one `film` spend per film, refunded when `makeFilm` throws or returns no usable beat.
